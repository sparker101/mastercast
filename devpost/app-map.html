Mastercast: App Map

A take-home guide to how this proof of concept fits together. Snapshot of commit a75a34f: code moves, so treat this as a map of where to look, not the last word.

What it is

A desktop app (Electron) for planning social posts across client projects. One post carries a text version and a publish status for each channel, so the core loop is: see today's posts, adapt the text per channel, copy it, publish by hand, and tick that channel off.

Two halves. The main process (main.js) is the desktop side: window, data file read/write, opening folders, clipboard. The renderer (index.html + app.js + styles.css) is every screen you click. They talk only through the tiny bridge in preload.js.

All data lives in one JSON file in the app's storage area (planner-data.json), seeded from data/seed.json on first run. Nothing you change ever enters the repo.

Reference route (3 stops)

  1. The status control renders in the modal. app.js → renderModal(), the status-seg block. One button per status in STAGE_ORDER; the listener below it mutates ch.status and re-renders.
  2. Saving crosses the bridge to the file. app.js → save() (250 ms debounce) → preload.js saveData → main.js ipcMain.handle('data:save') → DATA_PATH.
  3. The badge is computed, never stored. app.js → stageOf(post) takes the least-advanced channel status at render time, so a badge can never disagree with the channels.

To change this, start here

  • Add or rename a status: STAGE_ORDER and STAGE_LABEL at the top of app.js. Order matters: index 0 is the least advanced.
  • Add a network: drop the SVG in icons/, add it to icons/icons.js and NETWORK_LABEL in app.js, then use it in data/seed.json.
  • Change demo content: data/seed.json. Posts use dayOffset relative to first launch so a fresh clone always has something due today.
  • Restyle: the palette and spacing live in the :root variables at the top of styles.css.
  • New desktop capability (notifications, tray): handler in main.js, one line exposing it in preload.js, call it from app.js.

A practice to reuse

The plan assumed shell.openPath returns an error string for missing folders. On Windows it actually pops a blocking OS dialog, so the modal's error branch never ran. It was found because the app had an observation channel: a hidden-window smoke hook (PLANNER_SMOKE in main.js) that runs a script inside the real page and reports the result, plus a one-line probe recording what the handler actually received.

Reusable: when an agent builds behavior neither of you can fully predict, give it the smallest mechanical observation channel early: a script, a probe, a test. Agents verify what they can measure and guess at what they can't. Recorded in devpost/checklist.md > Revisions.

Run it again

npm install (once), then npm start in the project folder. Your real data lives outside the repo in Electron's userData folder; deleting that file reseeds the demo.

Verification harness used during the build

PLANNER_DATA_PATH points the data file somewhere safe, PLANNER_SMOKE names a JS file executed inside the page whose return value is printed as SMOKE_RESULT, and PLANNER_SMOKE_SHOT captures a screenshot. Same idea as the POOL_DATA_PATH testing convention in The Pool.
